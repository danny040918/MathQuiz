# 🧮 수학 퀴즈 게임 (Math Quiz Game)

## 1. 프로젝트 개요
파이썬(Python)을 활용하여 콘솔 환경에서 동작하는 퀴즈 게임입니다. 객체지향 프로그래밍(OOP)을 적용하여 클래스를 분리하였으며, 파일 입출력을 통해 데이터를 영구적으로 보관합니다.

## 2. 퀴즈 주제와 선정 이유
* **주제:** 기초 수학 문제
* **선정 이유:** 일상생활에서 자주 쓰이는 사칙연산, 도형의 기본 성질, 소수 개념 등을 퀴즈를 통해 재미있게 복습하고 두뇌를 단련하기 위해 선정했습니다.

## 3. 실행 방법
1. Python 3.x 버전이 설치되어 있어야 합니다.
2. 터미널(또는 명령 프롬프트)에서 프로젝트 폴더로 이동합니다.
3. 아래 명령어를 입력하여 게임을 실행합니다.
   ```bash
   python main.py

   하이하이하이요
   ```

## 🎮 클래스 역할 설명 (책임 분리)
이 게임은 코드를 깔끔하게 관리하기 위해 두 개의 클래스로 역할을 나누어(책임 분리) 만들었습니다.

- **`Quiz` 클래스 (문제 담당)**
  - 역할: 수학 문제 1개를 만드는 역할만 집중해서 맡습니다.
  - 기능: 랜덤으로 숫자를 뽑아 문제를 만들고, 진짜 정답을 계산하며, 플레이어가 쓴 답이 맞는지 틀렸는지 검사합니다.

- **`QuizGame` 클래스 (게임 진행 담당)**
  - 역할: 게임의 전체적인 흐름과 점수를 관리하는 매니저 역할을 합니다.
  - 기능: `Quiz` 클래스에게 "문제 하나 줘!"라고 부탁해서 화면에 보여주고, 플레이어의 점수를 기록하며, 게임 시작과 종료를 관리합니다.

## 🧩 로직 분리 기준 (모듈화 규칙)
이 프로그램은 코드가 복잡해지는 것을 막고 나중에 수정하기 쉽도록, 기능별로 코드를 나누는 **모듈화 규칙**을 지켜서 만들었습니다.

1. **입력 처리 로직 (Input)**
   - 사용자가 정답을 입력할 때, 숫자가 아닌 이상한 글자를 넣지 않았는지 검사합니다. (예외 처리)
   - 게임을 진행하는 코드와 섞이지 않게 따로 분리해서, 오류가 나도 게임이 튕기지 않고 안전하게 계속되도록 만들었습니다.

2. **게임 진행 로직 (Game Flow)**
   - 게임이 시작되고, 다음 문제로 넘어가고, 끝나는 전체적인 '흐름'만 관리합니다.
   - 문제 생성이나 입력 검사 같은 복잡한 일은 다른 곳에 맡기고, 오직 '게임 진행'에만 집중하도록 분리했습니다.

3. **데이터 및 저장 로직 (Data & Save)**
   - 문제의 진짜 정답이 무엇인지, 플레이어의 현재 점수가 몇 점인지 같은 '데이터'를 만들고 보관하는 부분입니다.
   - 화면에 글자를 보여주는 기능과 데이터를 보관하는 기능을 분리하여, 나중에 점수를 파일로 저장하거나 불러오기 쉽게 설계했습니다.


## 📝 커밋 메시지 규칙 (Commit Convention)
이 프로젝트는 변경 기록을 쉽게 파악할 수 있도록, 실무에서 자주 쓰이는 커밋 메시지 규칙을 적용했습니다.

### 1. 커밋 단위 (Scope)
- **1커밋 1기능:** 하나의 커밋에는 여러 가지 작업을 섞지 않고, '하나의 기능 추가' 또는 '하나의 버그 수정' 단위로 작게 나누어 커밋했습니다.

### 2. 커밋 메시지 작성 규칙 (Prefix)
커밋 메시지 앞에는 항상 아래의 [태그]를 붙여서 어떤 종류의 작업인지 한눈에 알 수 있게 작성했습니다.

- `feat:` 새로운 기능 추가 
  - *(예시: `feat: 최고 점수 확인 기능 추가`)*
- `fix:` 버그 수정 또는 에러/충돌 해결 
  - *(예시: `fix: README 병합 충돌 해결`)*
- `docs:` 문서(README.md 등) 내용 추가 및 수정 
  - *(예시: `docs: README에 커밋 메시지 규칙 추가`)*
- `refactor:` 코드 구조 개선 (기능은 그대로 두고 코드만 깔끔하게 정리)


## 🏛️ 클래스(Class)를 사용한 이유 (함수와의 차이점)
이 퀴즈 게임은 단순히 함수(Function)만 나열하지 않고, **클래스(Class)**를 설계하여 만들었습니다. 그 이유는 다음과 같습니다.

### 1. 클래스를 사용한 이유 (장점)
- **데이터와 기능의 묶음 (캡슐화):** 게임에는 '현재 점수' 같은 **데이터(변수)**와 '정답 확인하기' 같은 **기능(함수)**이 필요합니다. 클래스를 사용하면 이 두 가지를 하나의 상자 안에 깔끔하게 묶어서 관리할 수 있습니다.
- **상태 기억:** 게임이 진행되는 동안 플레이어의 점수를 계속 기억(`self.score`)해야 하는데, 클래스는 자기만의 기억 공간이 있어서 상태를 유지하기가 아주 좋습니다.

### 2. 함수(Function)만 사용했을 때와의 비교
- **함수만 사용할 때 (단점):** 함수는 한 번 실행되고 끝나버리기 때문에, '현재 점수'를 계속 기억하려면 변수를 이 함수 저 함수로 복잡하게 전달하거나 전역 변수(Global Variable)를 써야 해서 코드가 꼬이기 쉽습니다.
- **클래스를 사용할 때 (장점):** 클래스는 마치 게임 속 '캐릭터'처럼 자기 자신의 상태(점수)를 스스로 기억하고 행동할 수 있습니다. 따라서 게임처럼 '계속 변하는 상황'을 관리해야 하는 프로그램에서는 클래스를 쓰는 것이 코드를 이해하고 수정하기 훨씬 쉽습니다.



## 💾 데이터를 JSON으로 저장한 이유
이 퀴즈 게임에서는 최고 점수나 퀴즈 데이터를 저장할 때 **JSON** 형식을 선택했습니다. 그 이유는 다음과 같습니다.

### 1. JSON을 선택한 이유 (장점)
- **사람이 읽기 쉽다 (가독성):** JSON은 일반 텍스트 파일이고, 파이썬의 딕셔너리(`{ "키": "값" }`) 모양과 똑같이 생겼습니다. 그래서 메모장으로 열어봐도 누구나 쉽게 데이터를 읽고 수정할 수 있습니다.
- **가볍고 빠르다 (경량성):** 무겁고 복잡한 데이터베이스(DB) 프로그램 없이도, 아주 적은 용량으로 데이터를 빠르게 저장하고 불러올 수 있습니다.
- **호환성:** 파이썬뿐만 아니라 거의 모든 프로그래밍 언어에서 기본적으로 이해할 수 있는 아주 유명하고 표준적인 방식입니다.

### 2. JSON의 단점
- 사진이나 음악 같은 복잡한 데이터는 저장하기 어렵고, 데이터가 수십만 개로 엄청나게 많아지면 전용 데이터베이스(DB)를 쓰는 것보다 검색 속도가 느려질 수 있습니다. 
- 하지만 우리 퀴즈 게임처럼 간단한 최고 점수를 저장하는 데는 JSON이 가장 가볍고 완벽한 선택입니다!



## 🌿 브랜치(Branch)와 병합(Merge) 워크플로우
이 프로젝트를 진행하면서 코드를 안전하게 관리하기 위해 **브랜치(Branch)**를 만들고 **병합(Merge)**하는 방식을 사용했습니다.

### 1. 브랜치(Branch)를 생성한 목적
- **안전한 작업 공간 (평행 우주):** `main` 브랜치는 항상 에러 없이 잘 실행되어야 하는 '원본'입니다. 새로운 기능을 만들거나 버그를 고칠 때 원본을 직접 수정하면 게임이 망가질 위험이 있습니다. 
- 그래서 원본을 그대로 복사한 '브랜치'를 따로 만들어서 안전하게 작업했습니다. 이렇게 하면 코드를 망쳐도 원본(`main`)은 완벽하게 보호됩니다.

### 2. 병합(Merge)의 의미
- **완성된 작업 합치기:** 따로 만든 브랜치에서 새로운 기능을 다 만들고 테스트까지 무사히 마쳤다면, 그 완성된 코드를 다시 원본(`main`)에 합쳐야 합니다. 이 합치는 과정을 '병합(Merge)'이라고 합니다.

### 3. 프로젝트에 적용한 워크플로우 (작업 순서)
실제 프로젝트에서 다음과 같은 순서로 브랜치와 병합을 진행했습니다.
1. **브랜치 생성 및 이동:** `git checkout -b feature-test` (새로운 작업을 위한 안전한 공간 만들기)
2. **작업 및 커밋:** 코드 작성 후 커밋하여 기록 남기기 (`git add`, `git commit`)
3. **메인으로 돌아오기:** `git checkout main` (원본 브랜치로 이동)
4. **병합(Merge):** `git merge feature-test` (완성된 기능을 main에 하나로 합치기)

## 🚀 대량 데이터(퀴즈 1000개 이상) 확장 시 성능 분석 및 해결 전략

현재는 퀴즈 데이터가 적어서 JSON 파일을 사용해도 충분하지만, 만약 퀴즈가 1,000개 이상으로 늘어난다면 다음과 같은 문제가 발생할 수 있습니다.

### 1. 성능 및 메모리 문제 (JSON 검색의 한계)
- **메모리 과부하:** JSON 파일은 데이터를 읽을 때 파일 전체를 한 번에 컴퓨터 메모리(RAM)에 올려야 합니다. 데이터가 엄청나게 많아지면 메모리를 너무 많이 차지해서 게임이 느려지거나 멈출 수 있습니다.
- **검색 속도 저하:** 특정 난이도의 퀴즈를 찾으려면 처음부터 끝까지 하나씩 다 확인해야 합니다. (마치 두꺼운 책을 1페이지부터 끝까지 넘기며 찾는 것과 같아서 매우 비효율적입니다.)

### 2. 해결 방안 및 인덱싱(Indexing) 전략
대량의 데이터를 빠르고 안전하게 처리하기 위해 다음과 같은 전략을 도입할 수 있습니다.

- **데이터베이스(DB) 도입:** JSON 대신 `SQLite` 같은 데이터베이스(DB)를 사용합니다. DB는 전체를 다 읽지 않고 필요한 데이터만 쏙쏙 뽑아올 수 있어서 메모리를 아주 적게 씁니다.
- **인덱싱(Indexing) 적용:** 책 맨 뒤에 있는 '찾아보기(색인)' 기능처럼, 퀴즈의 '난이도'나 'ID'에 **인덱스(Index)**를 걸어둡니다. 이렇게 하면 1,000개의 퀴즈 중에서도 원하는 퀴즈를 순식간에 찾아낼 수 있습니다.
- **페이지네이션(Pagination):** 1,000개를 한 번에 화면에 불러오지 않고, 10개씩 쪼개서 불러오는 방식을 사용해 성능을 최적화합니다.



## 🛡️ 데이터 백업(Backup) 및 복구(Recovery) 전략

게임 중 컴퓨터가 갑자기 꺼지거나 에러가 발생하면 기록을 저장하는 `state.json` 파일이 망가질(손상될) 수 있습니다. 소중한 게임 기록을 지키기 위해 다음과 같은 백업 및 복구 절차를 마련했습니다.

### 1. 데이터 백업 전략 (예비 복사본 만들기)
- **수동 백업 (Manual Backup):** 중요한 게임 기록을 세웠을 때, 플레이어가 직접 `state.json` 파일을 복사하여 `state_backup.json`이라는 이름으로 안전한 폴더에 따로 저장해 둡니다.
- **자동 백업 (Automatic Backup):** 게임 프로그램이 종료될 때나 최고 점수가 갱신될 때마다, 코드 내부에서 자동으로 현재 상태를 `state_backup.json` 파일로 덮어쓰기 하여 저장하도록 설계할 수 있습니다.

### 2. 데이터 복구 및 초기화 절차
만약 `state.json` 파일이 손상되어 게임이 실행되지 않는다면 다음 순서로 해결합니다.

1. **복구(Recovery) 절차:** 
   - 손상된 `state.json` 파일을 삭제합니다.
   - 미리 만들어둔 `state_backup.json` 파일의 이름을 `state.json`으로 바꿉니다.
   - 게임을 다시 실행하면 마지막으로 백업된 시점부터 이어서 할 수 있습니다.
2. **완전 초기화(Reset) 절차:**
   - 만약 원본과 백업 파일이 모두 손상되었거나 삭제되었다면, 게임을 실행할 때 프로그램이 이를 감지합니다.
   - 자동으로 기본값(최고 점수 0점, 기본 플레이어 이름)을 가진 새로운 `state.json` 파일을 생성하여 게임이 멈추지 않고 처음부터 다시 시작될 수 있도록 안전장치를 마련했습니다.
